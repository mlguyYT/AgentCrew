# Documentation Checklist

## Purpose

This checklist helps agents keep documentation accurate and useful.

---

## Accuracy

- [ ] Documentation matches implemented behavior
- [ ] Setup commands are current
- [ ] File paths and links are current
- [ ] Examples still work conceptually
- [ ] Known limitations are stated

---

## Coverage

- [ ] README updated if user-facing behavior changed
- [ ] Usage docs updated if workflow changed
- [ ] API or configuration docs updated if interfaces changed
- [ ] Changelog or release notes updated if needed
- [ ] Migration notes exist when behavior changes incompatibly

---

## Quality

- [ ] Docs are concise
- [ ] Steps are ordered
- [ ] Terminology is consistent
- [ ] No secrets, raw customer data, or large logs are included

---

## Escalation

Escalate to Documentation Agent if:

- [ ] docs are part of acceptance criteria
- [ ] release notes or changelog are required
- [ ] public setup or usage instructions changed
- [ ] stale docs could cause users or agents to do the wrong thing
