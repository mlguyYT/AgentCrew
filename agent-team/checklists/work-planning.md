# Work Planning Checklist

## Purpose

Use this checklist before implementation when work needs sequencing or PR slicing.

---

## Checklist

- [ ] each phase has one clear outcome
- [ ] phases are small enough for focused PR review
- [ ] human-only decisions appear before dependent implementation
- [ ] risky migrations, security work, compatibility changes, or rollout steps are explicit
- [ ] validation evidence is listed per phase
- [ ] reviewer and specialist gates are listed when triggered
- [ ] docs or release notes are separate when public behavior changes
- [ ] next action is obvious
- [ ] no autonomous merge or human approval bypass is implied
